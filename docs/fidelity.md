# Research Fidelity and Project Scope

## Purpose

This repository is not intended to reproduce the Tensor Brain paper's reported numbers,
historical software stack, or VRD label design exactly. It aims to provide a small and solid
Tensor Brain core that can support three kinds of research:

1. Transfer the paper's experiments and tested capabilities to new data, especially video.
2. Extend the experiments with new questions about perception, memory, reasoning,
   continual learning, and cognition that may also produce broader insights for deep learning.
3. Extend the Tensor Brain itself, for example by comparing alternative dynamic-context
   mechanisms while retaining a paper-faithful reference implementation.

Fidelity therefore means preserving the model's concepts, state semantics, mathematical
operations, and experimentally meaningful execution order. It does not mean preserving
every historical dataset choice, label group, visual backbone, hyperparameter, or incidental
implementation detail.

## Evidence hierarchy

The papers are the primary source of truth, but they are not assumed to be infallible. Use
the following evidence hierarchy when implementing or reviewing a component:

1. The mathematical definition and conceptual role stated in the papers.
2. The paper algorithms, figures, appendices, and experimental descriptions considered
   together rather than in isolation.
3. The authors' original implementation as supporting evidence about intent.
4. A minimal implementation that makes the chosen interpretation explicit and testable.

If these sources conflict, or if an apparently paper-faithful choice is mathematically or
experimentally suspicious, do not silently choose an interpretation. Record the evidence,
explain the consequences, and ask for review before changing behavior.

## Decision categories

Every non-obvious decision should be described using one of these categories:

- **Paper-faithful:** directly implements an unambiguous paper equation or algorithm.
- **Reasonable interpretation:** resolves an ambiguity without changing the intended role.
- **Deliberate modernization:** replaces a historical component while preserving its boundary.
- **Experimental extension:** adds a new hypothesis, task, or model variant.
- **Suspected discrepancy:** the paper, appendix, equations, or reference code appear to
  conflict; implementation requires review before proceeding.

This vocabulary prevents a convenient engineering choice from being mistaken for a claim
about the original Tensor Brain.

## Stable scientific core

The following concepts should remain recognizable in code and in experiment schedules:

- `q` is the representation-layer preactivation, or pre-CBS.
- `gamma = sigmoid(q)` is the cognitive brain state (CBS).
- `h` is the original Tensor Brain's dynamic-context preactivation, not the CBS.
- `A[:, k] = a_k` is the learned embedding of symbolic index `k`.
- The same `A` is used for bottom-up index scoring and top-down index feedback - for now. Later we could eventually introduce additional layers in the bottom-up index scoring, i.e., introduce layers between q and A before we produce the index scores. Even, we could get scores without A. However, for the top-down index feeback, it is imperative that A is directly used, as it contains the index embeddings which need to be directly injected.
- Input integration, measurement, attention, and evolution are distinct paper operations.
- Evolution happens when processing moves between concept windows.
- The order of scene, subject, object, unary-label, and predicate operations is part of the
  scientific model and should remain explicit in experiment code.
- The original Tensor Brain recurrence remains available as the reference recurrent
  dynamic-context implementation.

The core should remain small. Abstract trainable components that are genuine experimental
variables; do not hide experimental schedules behind generic protocol runners or composers.

## Replaceable research boundaries

The following are deliberately replaceable without claiming to alter the core Tensor Brain
concepts:

- Perception: precomputed DINO features initially replace VGG and bounding-box CNN features.
- Dataset and ontology: PVSG or other video data may replace VRD, and label groups should be
  defined by the scientific question rather than copied from the original eight groups.
- Dynamic context: QTB feed-forward evolution, the original recurrence, and later xLSTM or
  Mamba variants may be compared behind the evolution boundary.
- Experiment design: original capabilities provide a starting map, but new cognitive and
  deep-learning hypotheses are first-class goals.
- Training infrastructure: dependencies may be modernized as long as they do not obscure the
  model or its execution order.

| Attention versus generative measurement: a schedule discrepancy between the papers | **Suspected discrepancy, unresolved** | The two papers order the top-down operations differently, and the repository currently implements only the original's reading. **Original TB:** Algorithm 1 performs one top-down step per concept window — score, sample, inject (`n_S(s) <- a_s^T sig(q~_S)`, `s* ~ softmax_beta(n_S)`, `q_S <- q~_S + a_{s*}`, lines 18-20). Section 5.3 then states that the semantic-attention approximation *"replaces line 20"*, making attention an **alternative** to the sampled injection. Line 30 gives the predicate window no top-down step at all. **QTB:** Algorithm 2 is "Input and Attention" (`q <- q + g(nu)` then `q <- q + sum_k a_k softmax(a_{0,k} + sum_l a_{l,k} sig(q_l))`), and Algorithm 3 is "Generative Measurement" (`k ~ softmax(...)`, then `q <- alpha q + beta a_k`, with `alpha = beta = 1` in the TB). The accompanying text is explicit that these are **sequential, not alternative**: "Algorithm 1 is executed first, followed by Algorithm 2. Finally, Algorithm 3 is executed, potentially multiple times, producing outcomes." Attention is part of input integration and precedes measurement; it does not stand in for it. **Implemented:** the original's reading. `P-SA` calls `TensorBrain.attend` (Algorithm 2 line 2) and `P-Samp` calls `TensorBrain.measure` (Algorithm 3) as mutually exclusive conditions, which is correct for the Section 6 perception transfer those experiments reproduce. Consequences that must not be misreported: the QTB sequential schedule has never been run; under QTB's reading the `integral-none` control is not a Tensor Brain at all, because Algorithm 2's attention is unconditional; and the top-down drive actually applied (4.0-6.5% of the pre-feedback state norm) is roughly a third of what the sequential schedule would apply, which matters because injection magnitude is the last surviving mechanical explanation for the measured feedback null. Resolving this requires a named sequential condition and review, not a silent change. Two further details are recorded to prevent confusion: Algorithm 2 sums over the complete index layer `sum_{k=1}^{N_S}`, so restricting attention to a candidate group is a postselection choice (QTB Equation 40's indicator `z`), and `beta` denotes the softmax inverse temperature in original Section 5.3 but the feedback gate in QTB Algorithm 3 - the repository's `feedback_gate` is the latter, while `selection="argmax"` realizes the former's `beta -> infinity` limit. |
| Feedback gate above one, shared by attention and measurement | Named departure from the stated QTB range | QTB Algorithm 3 constrains `0 <= beta <= 1`, chosen because it is the natural range between fully considering the injected embedding and ignoring it, not because a wider range breaks the Bayes-approximation derivation. The core already declares that it does not constrain gate values, so `--feedback-gate` admits `beta > 1`. It gates **both** top-down operations: Algorithm 3's measurement injection, and Algorithm 2's attention, which the paper writes ungated. Tying them is deliberate and is what makes a sweep meaningful. Training uses the differentiable attention approximation and the measurement modes are evaluation-only, so a measurement-only gate would have no training-time effect whatsoever and a sweep would produce identical runs. The cost is that attention and measurement magnitudes cannot be attributed separately; a distinct attention gate is the finer factorization if they ever need to move independently, and is not implemented. `beta = 1` reproduces both printed equations exactly. Any result at `beta > 1` must be reported as outside the stated range, and a positive one argues for revisiting either the range or the normalization that made the injection small, not that the printed equations were wrong. |
| Bottom-up versus top-down scale | Required diagnostic, currently unchosen | `integrate_input` implements `q' = q + mu g(nu)` and every PVSG experiment leaves `mu = 1`. The resulting ratio of visual drive to index-embedding norm is `27.7 : 1.0` at initialization and `34.0 : 2.4` at a selected checkpoint, so a single injected embedding perturbs the state by roughly 4-7%. That ratio was never chosen: it falls out of two independent decisions - inputs normalized to `sqrt(D) * L2-normalize(x)` with `D = 768`, and `A` initialized so each column has expected squared norm one. It cannot be corrected through the measurement gates, because QTB constrains `0 <= beta <= 1` and `beta = 1` is already the maximum. `mu` is the sanctioned experiment-owned lever, and any claim that top-down feedback is too weak to matter must report this ratio rather than treating it as a property of the architecture. |
| PVSG pair category index feedback | Experimental extension against the original, **paper-faithful against QTB** | Original Algorithm 1 samples a unary label `c*` at line 22 and never injects it, but p.18 defines `q̈_S = q_S + a_{c*}` as the sentence embedding and Section 5.2 uses that injection for chaining, so putting category feedback on the perception path is an extension rather than a paper-faithful step. **Revised:** against QTB this is not an extension at all. Algorithm 3 is "executed, potentially multiple times, producing outcomes… each outcome `k` corresponds to a distinct symbolic index", and each execution applies `q <- alpha q + beta a_k`. Sequential multi-label measurement with injection is therefore the QTB standard perception step, and the implemented category feedback is its two-outcome case. The classification depends on which paper is the reference; see the attention-versus-generative-measurement row. `IntegralTB` therefore scores every hierarchy group from the post-identity-feedback state, then optionally injects one decoded level before evolution. Each group is scored before its own feedback, so no readout confirms itself, and Algorithm 1 line 30's predicate window (`q_P = q̃_P`) receives no feedback. The injected level is `object_category/source` by default because the complementarity diagnostic showed source categories carry the predicate signal and because source and fine share 89 global columns. All thirteen loss terms are unchanged, so `integral-cat-sa` and `integral-id-cat-sa` remain comparable with the existing `integral-none` control, which is reused rather than retrained. Separately recorded suspected discrepancy: Algorithm 1 lines 18 and 25 score the subject and object over the same concept set `C` used for unary labels, justified on p.13 by generalized statements, whereas the Section 5.3 attention approximation states that only entity columns are considered. The implemented identity-only candidate set follows Section 5.3; widening it to the full concept set is the pending paper-faithful companion condition and is not implemented yet. |
| PVSG known-entity pair protocol | Paper-analogue transfer plus dataset-strengthened construction | The pair runner takes an explicit `--protocol`. `heldout_video` is the unchanged novel-entity regime and remains the VRD-E analogue: whole videos are reserved and PVSG identities are video-scoped, so no identity candidate can be correct and the identity readout is undefined at evaluation. `blocked` trains on `blocked/train_pairs` (the first 45% of each training video's frames) and reports one checkpoint on two sets: the same novel-entity development videos, and `blocked/evaluation_pairs` (the last 45% of the same videos, behind the 10% embargo), where both participants were observed before the boundary and therefore own index columns. This is the VRD-EX analogue and a stronger construction than the original: VRD-EX distorted copies of the training images (tb_original p.23), so "known entity" partly meant "nearly the same pixels", whereas blocked requires re-identification across a genuine temporal gap. Checkpoint selection stays on the novel-entity set for both protocols, so known-entity numbers are reported rather than selected for. Identity columns are enrolled from `blocked/train_objects` rather than from training pair participants, because a blocked evaluation pair only requires both participants to have been mask-visible before the boundary; enrolling from pairs alone would silently evaluate a filtered subset. The runner therefore records total identity columns and the subset supervised by a training pair, requires every training-pair participant to be enrolled, and refuses to run if any entity in a known-entity set owns no column. `result.json` is now nested by evaluation set for every protocol and condition; the four completed corrected pair runs predate that nesting. |
| PVSG known-entity pair reporting | Required reporting boundary | Where a protocol enrolls the evaluated entities, pair evaluation additionally scores both identity readouts with observation-, identity-, and video-aggregated accuracy, and reports the joint rate at which both participants are recognized. Predicate metrics are then partitioned two ways: by whether the same forward pass recognized both participants, and by how long the longer-unobserved participant had been absent (`0-2s`, `2-5s`, `5-10s`, `10s+` from the manifest's recorded delay). Both partitions are conditional associations, not causal interventions: the recognition partition conditions on a model output, and the delay partition conditions on a dataset property that also correlates with video length and motion. Strata report aggregates only, suppressing the per-predicate breakdown the full set reports. The delay axis has no counterpart in the original experiments, which had no temporal separation between enrollment and test. |
| PVSG feedback direction diagnostic | Required research diagnostic | `feedback_rows` reports mean pairwise cosine between the diagnostic batch's feedback vectors for every traced pathway, alongside the existing norm summaries. ## Experimental fidelity

Experiments should reproduce or extend capabilities rather than numerical results. Examples
include:

- perception with and without index feedback and dynamic context;
- semantic completion and nonvisual enrichment;
- episodic storage, recall, recency, and similarity-based retrieval;
- compositional and embedded symbolic reasoning;
- continual or self-supervised establishment of new indices;
- prediction, anticipation, and memory-supported decisions on video;
- controlled comparisons of alternative dynamic-context mechanisms.

Each experiment should state which Tensor Brain capability it tests, which paper operation it
uses, which parts are modernized, and which controls could falsify the proposed explanation.

## Review rule

Before implementing a suspicious or conflicting detail:

1. Cite the relevant equations, algorithms, appendix text, and reference-code behavior.
2. Describe the plausible interpretations and their observable consequences.
3. Recommend one option, but ask for review before modifying the implementation.
4. Record the approved resolution in this document and cover it with an equation-level or
   behavioral test.
